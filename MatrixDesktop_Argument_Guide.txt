MATRIXDESKTOP ARGUMENT GUIDE (desktop wrapper v1.2.0)
=====================================================

This file is embedded in both MatrixDesktop.exe and MatrixDesktopConfigurator.exe.
It is what `MatrixDesktop.exe --help-full` prints and what the configurator's `?`
button shows, so it is user-facing text, not developer notes. The authoritative
version number is <Version> in MatrixDesktop/MatrixDesktop.csproj; keep the line
above in step with it.

Scope
-----
This guide covers EVERY supported command-line argument in this Windows desktop build:

A) App flags (wrapper-level)
   - Consumed by the WinForms/WebView2 wrapper.
   - Control windowing, monitor targeting, exit behavior, cursor, DevTools.
   - NOT forwarded to the embedded Matrix web app.

B) Web flags (visualizer-level)
   - Forwarded to the embedded Matrix web app as URL query parameters.
   - These must match the web app’s expected parameter names EXACTLY (case-sensitive).

Companion configurator
----------------------
MatrixDesktopConfigurator.exe provides a standalone UI for building these
arguments, saving named presets, copying the generated command, and launching a
safe windowed test run. It stores presets beside the executable when possible,
or under LocalAppData\MatrixDesktop\Configurator when the publish folder is not
writable.


1) How to pass arguments
------------------------
The wrapper accepts multiple input styles (you can mix them):

Structured ZMatrix font/list arguments accept raw JSON or json64: followed by
unpadded base64url UTF-8 JSON (at most 64 KB decoded). The configurator encodes
these values in Copy commands so shell characters inside phrases stay literal.
Direct Test Argument and live preview retain structured JSON. Export .ps1 uses
Windows argument quoting and an ASCII-safe UTF-8 payload, preserving raw JSON
under both Windows PowerShell 5.1 and PowerShell 7.
Windows command lines are limited to 32767 UTF-16 characters; an oversized
generated command or direct launch reports that limit instead of truncating it.

1. Raw query string (single argument)
   - MatrixDesktop.exe "?version=3d&effect=mirror"
   - MatrixDesktop.exe "version=3d&effect=mirror"   (also accepted)
   Note: in Windows shells, the '&' character MUST be quoted.

2. Key/value pairs
   - MatrixDesktop.exe version=3d effect=mirror

3. GNU-style flags
   - MatrixDesktop.exe --version=3d --effect=mirror
   - MatrixDesktop.exe --version 3d --effect mirror

4. Windows-style flags
   - MatrixDesktop.exe /version=3d /effect=mirror

Precedence rules
- If the same key appears multiple times, the LAST value wins.
  Example: --fallSpeed 0.2 --fallSpeed 1.0 => effective fallSpeed is 1.0

Case sensitivity rules (IMPORTANT)
- Web flags are case-sensitive because the web app’s parser is case-sensitive.
  Use: animationSpeed
  Not: animationspeed


2) How values are parsed (numbers, booleans, lists)
---------------------------------------------------
Numbers
- Parsed as JavaScript parseFloat()/parseInt() in the web app.
- ZMatrix settings use finite whole-value parsing and reject trailing text such as 50%.
- Decimals are supported: 0.5, 1.25, -0.1
- Scientific notation usually works: 1e-2
- Percent signs are NOT a “percentage” feature.
  Example: "50%" becomes 50 (not 0.5). Avoid %.

Booleans
- For known boolean web flags (camera, volumetric, glyphFlip, clickRipples, loops, skipIntro, suppressWarnings, once, isometric):
  - Recommended: true / false
  - Also accepted via wrapper normalization, converted to true/false before the
    value reaches the web app:
      true  <= 1, y, yes, on
      false <= 0, n, no, off
    Matching is case-insensitive and surrounding whitespace is trimmed, so
    --camera YES and --camera " on " both work.
  - An EMPTY value normalizes to true.
    Example: --camera=   is treated as camera=true
  - Bare boolean flags are treated as true.
    Example: --volumetric  is treated as volumetric=true
  - Any other value is passed through to the web app unchanged, and the web app
    accepts a boolean only when the text is exactly "true" (case-insensitive).
    So --camera maybe and --camera 2 are both FALSE, silently. Stick to the
    forms listed above.

Comma-separated lists
- Color and palette/stripe values are passed as comma-separated lists without brackets.
  Example: --backgroundRGB 0,0,0
- NO WHITESPACE inside the list, not even after a comma. The shell, not the app,
  splits on spaces, so "--stripeColors 1,0,0, 1,1,0" arrives as two separate
  arguments: the wrapper reads only "1,0,0," as the value, and the trailing empty
  field makes the whole list invalid, so the flag is dropped. There is no warning.
  Alternatively quote the whole value: --stripeColors "1,0,0, 1,1,0" also works,
  because the parser trims each field. Unquoted and spaced does not.

Colors
- Matrix and UC3D color channels are 0..1 floats. So full red is 1,0,0 and NOT
  255,0,0. See section 4.7 for the per-flag formats (RGB triples, HSL triples,
  palette stops, stripe sequences).
- ZMatrix's zm*Color arguments use byte RGB triples, 0..255, matching its native controls.
- A stripe sequence is one flat comma-separated list of triples with no
  grouping punctuation. Six colors is eighteen numbers:
  MatrixDesktop.exe --effect stripes --stripeColors 1,0,0,1,0.5,0,1,1,0,0,1,0,0,0,1,0.5,0,0.5


3) App flags (wrapper-level; NOT forwarded to the web app)
----------------------------------------------------------
These flags control the desktop shell.

Windowing / monitor selection
- --wallpaper
  Default: OFF
  Meaning: run behind desktop icons across the virtual desktop, with a tray menu.
  Available with scene=matrix, scene=uc3d and scene=zmatrix. Does not replace the
  saved Windows wallpaper. Escape and ordinary typing do not close wallpaper mode.
  The last window-mode flag wins. Test Argument always uses a normal window.

- --wallpaper-input / --no-wallpaper-input
  Default: OFF
  Meaning: forward desktop pointer movement/clicks to interactive visual effects.
  Does not consume the desktop click or bring the wallpaper to the foreground.

- --wallpaper-pause-fullscreen / --no-wallpaper-pause-fullscreen
  Default: ON
  Meaning: automatically pause when a foreground application covers a monitor.

- --wallpaper-pause-battery / --no-wallpaper-pause-battery
  Default: OFF
  Meaning: pause while the workstation reports that it is running on battery.

- --process-priority auto|idle|below-normal|normal|above-normal|high|realtime
  Default: auto
  Meaning: auto uses Idle for wallpaper and Normal for other modes. This controls
  the host process, not a guarantee about WebView2 renderer or GPU scheduling.
  Windows may reject an elevated priority; the tray/log reports when it could not be applied.

- --borderless
  Aliases: --fullscreen, --span, --span-all, --spanall
  Default: ON
  Meaning: borderless window spanning the full virtual desktop (all monitors).

- --windowed
  Default: OFF
  Meaning: normal resizable window (useful for debugging).

- --single-monitor
  Aliases: --singlemonitor
  Default: OFF
  Meaning: borderless fullscreen on the PRIMARY monitor only.

- --monitor N
  Default: none
  Meaning: borderless fullscreen on monitor index N (0-based; uses Screen.AllScreens ordering).
  Notes:
  - This implies single-monitor mode.
  - Monitor ordering can change when Windows display layout changes.

- --working-area
  Aliases: --workingarea
  Default: OFF
  Meaning: uses WorkingArea instead of full monitor bounds (so taskbars remain visible).
  Applies to borderless modes.

Z-order (always on top)
- --topmost
  Default: OFF
  Meaning: window stays above other windows.

- --no-topmost
  Aliases: --notopmost
  Default: OFF
  Meaning: explicitly disables topmost.

Cursor
- --hide-cursor
  Aliases: --hidecursor
  Default: OFF
  Meaning: hides the mouse cursor while the app runs.

- --show-cursor
  Aliases: --showcursor
  Default: ON (unless you explicitly hid it)
  Meaning: ensures the app does not hide the cursor.

Exit behavior for ordinary window/fullscreen launches
- This build uses a Windows low-level keyboard hook (WH_KEYBOARD_LL). It is intended to:
  - exit on REAL keyboard hardware input
  - ignore typical software-injected keystrokes by filtering LLKHF_INJECTED /
    LLKHF_LOWER_IL_INJECTED events (for example, many SendInput/keybd_event
    automation events)
  - keep working when focus is inside native child windows such as WebView2
  Note: virtual HID keyboard drivers can look like physical hardware to
  user-mode code, so they may not be distinguishable from real keyboards.
  Wallpaper and child preview modes do not install this keyboard exit hook.
  A genuine /s screensaver also exits on session input changes, including
  delivered software-injected keyboard or mouse events.

- --exit-on-any-key
  Aliases: --exit-on-anykey, --anykey-exit
  Default: ON
  Meaning: any PHYSICAL keypress closes the app.

- --no-exit-on-any-key
  Aliases: --no-anykey-exit
  Default: OFF
  Meaning: disables the any-key exit.

- --exit-on-esc
  Aliases: --esc-exit, --exitonesc, --escexit
  Default: ON
  Meaning: physical ESC closes the app (useful if any-key exit is disabled).

- --no-esc-exit
  Aliases: --noesc-exit, --no-esc
  Default: OFF
  Meaning: disables ESC-to-exit.

- --foreground-key-exit
  Aliases: --require-foreground-key-exit, --foregroundkey-exit,
           --requireforeground-key-exit, --no-global-key-exit, --noglobal-key-exit
  Default: ON
  Meaning: only exit on keypress while MatrixDesktop is the foreground (active) app.

- --global-key-exit
  Aliases: --background-key-exit, --global-exit-on-key, --globalkey-exit
  Default: OFF
  Meaning: exit on physical keypress even when MatrixDesktop is NOT focused.
  Risk: this can be surprising because typing in other apps will close MatrixDesktop.

WebView2 DevTools
- --no-devtools
  Aliases: --nodevtools
  Default: OFF
  Meaning: disables WebView2 DevTools (more locked-down distribution).

- --devtools
  Default: ON
  Meaning: explicitly enables DevTools.

Help
- --help
  Aliases: -h, /?, help
  Meaning: shows the built-in help dialog, a short summary of the wrapper flags.
  Note: this is a MODAL dialog. The process waits for you to dismiss it, so do
  not use it in a script or an unattended test.

- --help-full
  Aliases: --help-arguments
  Meaning: shows this entire argument guide in a scrollable dialog, read from
  the copy embedded in the executable. No sibling .txt file is required.
  Checked before --help, so --help-full wins if both are passed.
  Note: also modal. Same caveat as --help.


4) Web flags (forwarded to the embedded Matrix web app)
-------------------------------------------------------
These flags control the visualizer.

IMPORTANT: parameter names are case-sensitive.


4.1 Core selection
------------------
version (string)
- Key: version
- Default: classic (if missing/unknown)
- Meaning: selects a preset (“version”) that changes multiple internal settings.
- Known values in this build:
  classic, 3d, megacity, neomatrixology, operator, nightmare, paradise,
  resurrections, trinity, morpheus, bugs, palimpsest, twilight, holoplay
  Aliases: throwback=operator, updated=resurrections, 1999=operator, 2003=classic, 2021=resurrections
- Examples:
  MatrixDesktop.exe --version resurrections
  MatrixDesktop.exe --version 3d

  Looking Glass calibration is limited to 1024 quilt views with at least one
  pixel per tile axis. Invalid calibration reports a warning and uses ordinary
  rain. Physical Looking Glass hardware was not part of local verification.

font (string)
- Key: font
- Default: matrixcode (or the version’s font override)
- Meaning: chooses the glyph set.
- Known values in this build:
  matrixcode, resurrections, gothic, coptic, megacity,
  huberfishA, huberfishD, gtarg_tenretniolleh, gtarg_alientext, neomatrixology
- Example:
  MatrixDesktop.exe --font gothic

effect (string)
- Key: effect
- Default: palette (if missing/unknown)
- Meaning: selects the post-processing effect.
- Known values in this build:
  palette, plain, none, stripes, customStripes, pride, trans, transPride, image, mirror
  Notes:
  - effect=none shows a debug/behind-the-scenes view.
  - effect=mirror can use the webcam if camera=true.
  - effect=image uses url=... for the image.
- Example:
  MatrixDesktop.exe --effect stripes --stripeColors 1,0,0,1,1,0,0,1,0

renderer (string)
- Key: renderer
- Default: regl
- Meaning:
  - regl  => WebGL backend
  - webgpu => WebGPU backend (only if the machine supports WebGPU; otherwise it falls back to regl)
- Examples:
  MatrixDesktop.exe --renderer webgpu
  MatrixDesktop.exe --renderer regl


4.2 Layout and performance knobs
--------------------------------
numColumns (integer)
- Key: numColumns
- Aliases: width
- Default: 80 (varies by version)
- Meaning: base grid dimension (it drives BOTH rows and columns in the 2D mode).
- Range: clamped to 1–256.
- Performance: high impact. Cost grows roughly with numColumns^2.
- Recommended ranges:
  40–120 for most machines; go lower if running multiple monitors at high resolution.
- Examples:
  MatrixDesktop.exe --numColumns 60
  MatrixDesktop.exe --width 120

resolution (number)
- Key: resolution
- Default: 0.75
- Meaning: render resolution scale factor.
  - 1.0 = full resolution (devicePixelRatio-aware)
  - 0.5 = half resolution (faster, blurrier)
  - >1.0 = supersampling (sharper, slower)
- Range: clamped to 0.05–2.
- Accepts decimals. Avoid %.
- Example:
  MatrixDesktop.exe --resolution 0.6

fps (number)
- Key: fps
- Default: 60
- Range: clamped to 0–60
- Meaning: frame rate cap.
  - 60 = full speed
  - 30 = half-rate
  - 0 = effectively “do not render” (tends to look frozen)
- Example:
  MatrixDesktop.exe --fps 30

bloomSize (number)
- Key: bloomSize
- Default: 0.4
- Range: clamped to 0–1
- Meaning: bloom blur scale / spread.
- Performance: moderate impact.
- Note: if bloomSize <= 0, bloomStrength is forced to 0.

bloomStrength (number)
- Key: bloomStrength
- Default: 0.7
- Range: clamped to 0–1
- Meaning: bloom intensity.

ditherMagnitude (number)
- Key: ditherMagnitude
- Default: 0.05
- Range: clamped to 0–1
- Meaning: adds noise to reduce visible gradient banding.


4.3 Motion controls (the “speed knobs”)
---------------------------------------
General rule:
- Higher positive numbers => faster motion
- Lower positive numbers => slower motion
- Decimals are supported.
- Percent signs are not.

animationSpeed (number)
- Key: animationSpeed
- Default: 1
- Meaning: global multiplier applied to simulation time.
  Think of it as “master speed”.
- Effective motion is roughly:
  effective fall ≈ animationSpeed * fallSpeed
  effective cycle ≈ animationSpeed * cycleSpeed
  effective forward ≈ animationSpeed * forwardSpeed
- Example:
  MatrixDesktop.exe --animationSpeed 0.5

fallSpeed (number)
- Key: fallSpeed
- Default: 0.3 (varies by version)
- Meaning: rate at which raindrops progress down the columns.
- Negative values are allowed and tend to reverse direction (experimental but works).
- Example:
  MatrixDesktop.exe --fallSpeed 1.0

cycleSpeed (number)
- Key: cycleSpeed
- Default: 0.03 (varies by version)
- Meaning: how quickly glyphs change to new symbols.
- Negative values are accepted but not generally useful (treat as experimental).
- Example:
  MatrixDesktop.exe --cycleSpeed 0.01

forwardSpeed (number)
- Key: forwardSpeed
- Default: 0.25
- Meaning: forward motion speed in volumetric (3D) mode.
- Only meaningful when volumetric=true (or version=3d).
- Example:
  MatrixDesktop.exe --version 3d --forwardSpeed 0.08

raindropLength (number)
- Key: raindropLength
- Aliases: dropLength
- Default: 0.75
- Meaning: controls vertical raindrop scale and spacing within columns.
  Practical intuition:
  - smaller values => shorter/tighter drops
  - larger values => longer/sparser drops
- Example:
  MatrixDesktop.exe --raindropLength 1.2

slant (number; degrees)
- Key: slant
- Aliases: angle
- Default: 0
- Meaning: slants the rain/grid by degrees.
  - Positive vs negative changes direction of tilt.
  - Values are interpreted as DEGREES and converted internally to radians.
- Example:
  MatrixDesktop.exe --slant 15


4.4 3D controls
---------------
volumetric (boolean)
- Key: volumetric
- Default: false (true in version=3d)
- Meaning: enables the volumetric/3D rendering mode.
- Examples:
  MatrixDesktop.exe --volumetric true
  MatrixDesktop.exe --version 3d

density (number)
- Key: density
- Default: 1
- Meaning: in volumetric mode, multiplies the number of effective columns to increase depth density.
- Range: clamped to 0.01–8.
- Note: when effect=none (debug view), density is effectively forced to 1.
- Performance: high impact in volumetric mode.
- Example:
  MatrixDesktop.exe --version 3d --density 2

isometric (boolean)
- Key: isometric
- Default: false
- Meaning: when volumetric=true, switches to an isometric-like/orthographic camera style.
- Example:
  MatrixDesktop.exe --version 3d --isometric true


4.5 Glyph transforms
--------------------
glyphFlip (boolean)
- Key: glyphFlip
- Default: false
- Meaning: horizontally flips glyphs.
- Example:
  MatrixDesktop.exe --glyphFlip true

glyphRotation (number; degrees)
- Key: glyphRotation
- Default: 0
- Range: clamped to >= 0 (negative values become 0; use 270 instead of -90)
- Meaning: rotates each glyph in-place (degrees).
- Example:
  MatrixDesktop.exe --glyphRotation 90


4.6 Camera, click ripples, and external image
---------------------------------------------
camera (boolean)
- Key: camera
- Default: false
- Meaning: enables webcam capture (used by effect=mirror).
- Notes:
  - If camera permission is blocked/denied, the app will continue without the camera.
- Examples:
  MatrixDesktop.exe --effect mirror --camera true
  MatrixDesktop.exe --version updated --effect mirror --camera true

clickRipples (boolean)
- Key: clickRipples
- Default: false
- Meaning: enables click-triggered ripples in normal rain effects without using effect=mirror.
- Notes:
  - Applies to non-mirror effects such as stripes, palette, and image.
  - effect=mirror keeps its existing click ripple behavior.
- Examples:
  MatrixDesktop.exe --windowed --effect stripes --clickRipples true
  MatrixDesktop.exe --windowed --effect palette --clickRipples

clickRippleShape (string)
- Key: clickRippleShape
- Default: circle
- Accepted values: circle, box, triangle, star
- Meaning: chooses the shape of click-triggered ripples for non-mirror rain effects.
- Example:
  MatrixDesktop.exe --windowed --effect stripes --clickRipples true --clickRippleShape box
  MatrixDesktop.exe --windowed --effect stripes --clickRipples true --clickRippleShape star

url (string)
- Key: url
- Meaning: image URL used by effect=image.
  In this desktop wrapper, you can reference local assets in the web folder too.
  Example local asset path: assets/sand.png
- Examples:
  MatrixDesktop.exe --effect image --url assets/sand.png
  MatrixDesktop.exe --effect image --url https://upload.wikimedia.org/.../EagleRock.jpg


4.7 Color / palette / stripes
-----------------------------
Color value conventions
- The engine generally expects color channel values as 0..1 floats (not 0..255).
  - RGB: R,G,B each 0..1
  - HSL: H,S,L each 0..1  (Hue is normalized; 0.0 and 1.0 are both “red”)

backgroundColor (RGB)
- Key: backgroundColor
- Alias: backgroundRGB
- Value format: R,G,B (floats)
- Example:
  MatrixDesktop.exe --backgroundRGB 0,0,0

backgroundHSL (HSL)
- Key: backgroundHSL
- Value format: H,S,L (floats)
- Example:
  MatrixDesktop.exe --backgroundHSL 0.33,1,0.1

cursorColor (RGB)
- Key: cursorColor
- Alias: cursorRGB
- Value format: R,G,B

cursorHSL (HSL)
- Key: cursorHSL
- Value format: H,S,L

glintColor (RGB)
- Key: glintColor
- Alias: glintRGB
- Value format: R,G,B

glintHSL (HSL)
- Key: glintHSL
- Value format: H,S,L

cursorIntensity (number)
- Key: cursorIntensity
- Default: 2
- Range: clamped to >= 0
- Meaning: brightness multiplier for cursor glow.
- Example:
  MatrixDesktop.exe --cursorIntensity 3

glyphIntensity (number)
- Key: glyphIntensity
- Range: clamped to >= 0
- Meaning: brightness multiplier for the glyphs themselves, completing the set alongside
  cursorIntensity and glintIntensity. 1 is the default and leaves the render unchanged;
  0 removes the glyphs entirely, leaving only the cursor, glint and background; values
  above 1 brighten the glyphs until they clamp at white.
- Applies to: the palette and stripe effects, in both renderers. This is exactly where
  cursorIntensity and glintIntensity apply. The image and mirror effects have no glyph
  colour term to scale, so it has no effect there.
- Example:
  MatrixDesktop.exe --glyphIntensity 2

palette (RGB gradient)
- Key: palette
- Alias: paletteRGB
- Value format: repeating groups of 4 numbers:
  R,G,B,at,R,G,B,at,...
  where 'at' is a stop position (typically 0..1).
- NO SPACES anywhere in the value. A space after a comma makes the shell split
  the token, the wrapper sees only the first fragment, and the whole list is
  then rejected as malformed.
- Example (3 stops):
  MatrixDesktop.exe --palette 0.1,0,0.2,0,0.2,0.5,0,0.5,1,0.7,0,1

paletteHSL (HSL gradient)
- Key: paletteHSL
- Value format: H,S,L,at,H,S,L,at,...

stripeColors (RGB stripes)
- Key: stripeColors
- Aliases: stripeRGB, colors
- Value format: repeating groups of 3 numbers:
  R,G,B,R,G,B,R,G,B,...
- NO SPACES anywhere in the value, for the same reason as palette above.
- Example (red/yellow/green):
  MatrixDesktop.exe --effect stripes --stripeColors 1,0,0,1,1,0,0,1,0

stripeHSL (HSL stripes)
- Key: stripeHSL
- Value format: H,S,L,H,S,L,...

5) A few high-signal recipes
----------------------------
A) Performance-first (especially useful across multiple monitors)
- Reduce render scale and bloom:
  MatrixDesktop.exe --resolution 0.6 --bloomSize 0.2 --fps 45

B) Cinematic slow motion
  MatrixDesktop.exe --animationSpeed 0.5

C) Fast rain, slow glyph changes
  MatrixDesktop.exe --fallSpeed 1.0 --cycleSpeed 0.01

D) 3D subtle forward drift
  MatrixDesktop.exe --version 3d --forwardSpeed 0.08 --density 1.2

E) Stripes
  MatrixDesktop.exe --effect stripes --stripeColors 1,0,0,1,1,0,0,1,0

F) Image effect using a local bundled asset
  MatrixDesktop.exe --effect image --url assets/mesh.png


6) Notable “gotchas” (practical warnings)
-----------------------------------------
- Web parameter keys are case-sensitive. “animationspeed” will be ignored; “animationSpeed” will work.
- Never put a space inside a comma-separated value unless you quote the whole
  value. An unquoted “--stripeColors 1,0,0, 1,1,0, 0,1,0” is silently dropped:
  the shell splits it, the wrapper keeps only the first fragment, and the
  trailing empty field invalidates the list. This is the single most common way
  a copied example fails with no error message.
- Avoid percent signs in numeric values. “50%” becomes 50.
- Unsafe density, numColumns, and resolution values are clamped before rendering.
- forwardSpeed has no visible effect unless volumetric=true.
- isometric has no visible effect unless volumetric=true.
- Some internal config properties exist but are NOT exposed as URL params in this build
  (e.g., glintIntensity, baseTexture, glintTexture, brightness/contrast controls, low-level ripple tuning knobs).
  Changing those requires editing web/js/config.js.

UC3D scene options
==================

- Key: scene
- Default: matrix
  Rendering scene: matrix, uc3d or zmatrix. UC3D uses its own camera, image formation and glyph renderer.
  ZMatrix uses persistent 2D pixels, independent stream timing and native Windows fonts.
  Selecting uc3d applies its scene profile unless explicitly overridden:
  uc3dControls=original, uc3dAmount=500, uc3dGlyphSize=12,
  uc3dFallSpeed=6, uc3dForwardSpeed=6, bloomStrength=0,
  volumetric=true, codeColor=0.501961,0,1,
  cursorColor=1,0.501961,1, sidewaysMovement=true, randomForwardMovement=true,
  pictureMonochrome=false, uc3dPictureDelay=60, pictureDuration=30.
  Values come from the owner's installed screensaver settings captured on
  2026-10-23. Original controls use independent amount and glyph size.
  Explicit generic layout/motion options select legacy controls unless a native
  option or uc3dControls explicitly selects original. Saved customized presets
  retain legacy behavior. Other Default entries describe the ordinary Matrix scene.

- Key: uc3dControls
- Default: original
  UC3D: original uses native slider units and stream simulation; legacy retains
  generic numColumns, density, fallSpeed, forwardSpeed and raindropLength behavior.

- Key: uc3dAmount
- Default: 500
  UC3D original: More/Less slider, 100 to 1500 streams, independent of glyph size.
  Streams enter gradually over ten seconds; perspective and culling affect coverage.

- Key: uc3dGlyphSize
- Default: 12
  UC3D original: glyph size, 10 to 40. World half-size is value times 0.01.

- Key: uc3dFallSpeed
- Default: 6
  UC3D original: falling speed slider, 0 to 150. Zero still falls; randomized
  per-stream world speed is 2 + (random integer below slider + 30) times 0.1.

- Key: uc3dForwardSpeed
- Default: 6
  UC3D original: forward/backward slider, 0 to 120, neutral 60. Target world
  speed is (value - 60) times 0.1. Requires 3D and forward movement; random
  forward movement chooses its own target and disables this slider.

- Key: uc3dPictureScale
- Default: 100
  UC3D original: Large / Small picture slider, 100 to 300. Higher values shrink
  the image grid, as in the original; it is a sampling divisor, not zoom percent.

- Key: uc3dPictureDelay
- Default: 60
  UC3D original: delay between picture sequences, 0 to 120 seconds.

ZMatrix controls
----------------
These settings apply only to scene=zmatrix. Existing Matrix and UC3D values stay
in saved presets but are omitted from ZMatrix launch commands. Shared renderer,
resolution, fps, once and suppressWarnings still apply. Simulation refresh and
presentation FPS are separate: raising FPS does not accelerate the streams.

- Key: zmMaxStream
- Default: 1000
  Maximum active streams, 1 to 4096. At most one new stream starts per simulation tick.

- Key: zmSpeedVariance
- Default: 5
  Random per-stream wait, 0 to 120 ticks. A stream assigned wait N moves every N+1 ticks.

- Key: zmRefreshTime
- Default: 50
  Milliseconds per simulation tick, 10 to 1000. Default is 20 ticks per second.

- Key: zmMonotonousCleanupEnabled
- Default: false
  Restore a cell a fixed distance behind each stream. Can run with randomized cleanup.

- Key: zmBackTrace
- Default: 40
  Fixed cleanup distance, 0 to 4096 glyphs. Applies when fixed cleanup is enabled.

- Key: zmRandomizedCleanupEnabled
- Default: false
  Restore a cell at a randomized distance behind each stream.

- Key: zmLeading
- Default: 10
  Minimum randomized cleanup distance, 0 to 4096 glyphs.

- Key: zmSpacePad
- Default: 30
  Extra randomized cleanup distance, 0 to 4096 glyphs. This is not horizontal spacing.

- Key: zmSpecialStringProbability
- Default: 0.1
  Fraction of streams eligible to emit vertical phrases, 0 to 1. Eligible streams
  attempt a phrase once per movement with probability 1 / visible row count.

- Key: zmCharacters
  JSON array of unique single BMP characters. Default is the original 40-character
  set, "1234567890ABCDEFGHIJKLMNOPQRSUTVWXYZabcd". At most 512 characters.
  Use the configurator's character editor to avoid hand-escaping JSON.

- Key: zmPhrases
  JSON array of phrase strings. Default is ["The matrix has you"]. Empty array
  disables phrases and remains empty after reload. At most 64 phrases, 256 BMP
  characters each, and 1024 distinct special glyphs in total.

- Key: zmBackgroundMode
- Default: bitmap
  bitmap uses the Windows wallpaper captured with PaintDesktop, without icons or
  application windows. color uses zmBackgroundColor. Browser previews report a
  fallback when native wallpaper capture is unavailable.

- Key: zmBlendMode
- Default: or
  xor, and or or: bytewise RGB operations matching GDI raster operations. With
  transparent bitmap background, AND/OR use the donor's direct-overlay behavior.
  Color background ignores the blend selection. This is not Canvas2D compositing xor.

- Key: zmOpaqueBackground
- Default: false
  Select opaque bitmap blending. In solid-color mode, clear each glyph cell to
  zmBackgroundColor before drawing. The original background-alpha setting was a
  threshold at 128; it was not continuous transparency.

- Key: zmForegroundColor
  Byte RGB, default 187,255,187. Bright ordinary glyphs.

- Key: zmFadeColor
  Byte RGB, default 0,128,0. Newly randomized dim glyphs replacing previous heads.

- Key: zmBackgroundColor
  Byte RGB, default 0,0,0. Solid background and opaque glyph-cell background.

- Key: zmSpecialForegroundColor
  Byte RGB, default 251,255,251. Bright phrase glyphs.

- Key: zmSpecialFadeColor
  Byte RGB, default 208,244,208. Dim phrase glyphs.

- Key: zmRedGain
- Default: 1
  Red multiplier after speed-linked dimming, -4 to 4. Output clamps to byte RGB.

- Key: zmGreenGain
- Default: 1
  Green multiplier after speed-linked dimming, -4 to 4.

- Key: zmBlueGain
- Default: 1
  Blue multiplier after speed-linked dimming, -4 to 4.

- Key: zmRedOffset
- Default: 0
  Red offset after gain, -255 to 255.

- Key: zmGreenOffset
- Default: 0
  Green offset after gain, -255 to 255.

- Key: zmBlueOffset
- Default: 0
  Blue offset after gain, -255 to 255.

- Key: zmFont
  JSON Windows LOGFONT descriptor for ordinary glyphs. Default face Matrix Code
  Font, height -7, weight 400, charSet 1. The font is loaded privately by this app.

- Key: zmSpecialFont
  JSON Windows LOGFONT descriptor for phrase glyphs. Default face Terminal,
  height -8, weight 400, charSet 1. Windows may substitute an unavailable face;
  the resolved face and warnings are reported by the native renderer.

Both font descriptors accept height, width, escapement, orientation, weight,
italic, underline, strikeOut, charSet, outPrecision, clipPrecision, quality,
pitch, family and name. Heights use 96-DPI logical units, signed -256 to 256;
negative heights request character height. Width is 0 to 256, angles are tenths
of a degree (-3600 to 3600), weight is 0 to 1000, byte fields are 0 to 255,
pitch is 0 to 3, family is the high nibble 0 to 240, and face names are at most
31 characters. The configurator provides named controls for every field.
Native atlases retain RGB coverage and actual glyph ink bounds, including
rotation. Browser font fallback is explicitly approximate. Resource bounds
are four 2048-square atlas pages per font; excess glyph ink produces an error.

Screensaver entrypoints
-----------------------
The published MatrixDesktop.scr sits beside MatrixDesktop.exe and its runtime
files. Keep that directory together. Windows calls /s for fullscreen animation,
/c (optionally /c:HWND) for the configurator, and /p HWND for a real child preview.
Double-clicking the .scr without arguments also opens its configuration.
The configurator's explicit Use for screensaver action saves the current draft
to LocalAppData\MatrixDesktop\screensaver-profile.json and selects this .scr for
the current user. Normal launch, live preview and Test Argument do not register it.
The explicit Restore previous screensaver action restores the saved selection;
it refuses to overwrite a later screensaver choice made outside this app.
CLI equivalents: --register-screensaver and --restore-screensaver. Registration
uses an existing saved profile, or the default Matrix scene when none was saved.
